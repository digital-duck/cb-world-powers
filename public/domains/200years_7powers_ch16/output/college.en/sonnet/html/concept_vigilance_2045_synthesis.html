Vigilance 2045 Synthesis

The five patterns compiled in this chapter are not a forecast — they are a checklist assembled by tracing actual event chains through the primitives introduced in ch09–15, then asking which recurring structures showed up often enough to name. Treating them as predictions would be a category error: a prediction claims something about the future, while a checklist item makes a narrower, testable claim about the present — "this structure, built from these specific primitives, recurs across the traced chains we have so far." That claim is falsifiable in a precise sense: for each pattern, you can point to the primitives it depends on and ask whether new traced chains still exhibit the pattern once those primitives are re-examined or updated.

Consider a concrete instance. Suppose Pattern 3 in the chapter claims that "resource-contention chains resolve via priority inheritance within three hops of the blocking node." This is falsifiable because you can define exactly what would break it: a newly traced chain where a resource-contention event resolves in more than three hops, or resolves through some mechanism other than priority inheritance. If ch09–15 add ten new rows next year and one violates the three-hop bound, the pattern is not "mostly right" — it is falsified as stated and must be revised or narrowed (e.g., restricted to chains below a certain contention depth).

The discipline this demands is procedural, not mathematical: each time a new row is appended to the living chapters, re-run the pattern against it rather than assuming the pattern still holds. This is the same falsification logic used throughout empirical science — a rule earns its place in the checklist by surviving repeated attempts to break it, not by having been true once.

Practically, this means the five patterns should be read with an implicit tag: "true of the traced chains as of the last audit date." When you use this checklist — say, to decide whether a new incident matches a known failure mode — first check whether the primitives the matching pattern cites have themselves changed since the chapter was last updated. If primitive P4 (the definition of a "blocking node," for instance) was revised in ch12, any pattern built on P4 needs re-verification before you trust it, even if no one has explicitly retracted it yet.
